# AWS S3 & Cloud Storage Integration

## 1. Storage Architecture
tenderX isolates documents using hierarchical, predictable S3 object keys:
```
s3://<bucket-name>/
    organizations/{organization_id}/
        tenders/{tender_id}/
            documents/{document_id}/
                versions/{version_number}/{original_filename}
        vendors/{vendor_id}/
            documents/{document_id}/
                versions/{version_number}/{original_filename}
```

## 2. Server-Side Encryption (SSE-KMS)
- All objects are written using AWS Key Management Service (`SSE-KMS`).
- Encryption keys are never stored in source code, databases, or frontend code.
- Headers enforced:
  `x-amz-server-side-encryption: aws:kms`
  `x-amz-server-side-encryption-aws-kms-key-id: <KMS-ARN>`

## 3. Storage Provider Abstraction
The backend implements `StorageProvider` (defined in `backend/documents/services/storage.py`):
- `S3StorageProvider`: Production implementation utilizing `boto3`.
- `LocalStorageProvider`: Local development and CI/CD testing fallback supporting byte persistence and tokenized URLs without requiring cloud infrastructure.
